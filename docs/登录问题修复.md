## 🔍 根因分析

### 问题 #1 & #3: `current_user` 缓存机制

```mermaid
sequenceDiagram
    participant Req as 请求
    participant SetLog as set_current_user_for_logs
    participant Auto as auto_login_with_tai_hu_token
    participant Provider as CurrentUserProvider
    participant Preload as ApplicationLayoutPreloader
    
    rect rgb(255, 200, 200)
        Note over Req,Preload: ❌ 修复前的执行顺序（有问题）
        Req->>SetLog: 1️⃣ before_action
        SetLog->>Provider: current_user?
        Provider-->>SetLog: nil (无Cookie)
        Note right of Provider: 🔴 缓存 nil 到 env
        
        Req->>Auto: 2️⃣ before_action
        Auto->>Auto: 解析太湖header
        Auto->>Auto: log_on_user(user)
        Note right of Auto: 设置Cookie ✅<br/>但缓存仍是 nil ❌
        
        Req->>Preload: 3️⃣ before_action
        Preload->>Provider: current_user?
        Provider-->>Preload: nil (返回缓存)
        Note right of Preload: 🔴 guardian.authenticated? = false<br/>不预加载 currentUser
    end
```

**根本原因**: 
> `set_current_user_for_logs` 在太湖认证 `before_action` **之前**执行，调用了 `current_user`，导致 `nil` 被缓存。后续即使登录成功，缓存也不会更新。

### 问题 #2: AnonymousCache 中间件

```mermaid
flowchart TD
    subgraph 问题流程
        A[请求到达] --> B{有 _t Cookie?}
        B -->|否| C[AnonymousCache 中间件]
        C --> D{命中缓存?}
        D -->|是| E[🔴 直接返回缓存页面]
        E --> F[请求不到达 Controller]
        F --> G[auto_login 不执行]
        G --> H[用户看到未登录状态]
    end
    
    style E fill:#ffcdd2,stroke:#b71c1c,stroke-width:3px
    style G fill:#ffcdd2,stroke:#b71c1c,stroke-width:3px
    style H fill:#ffcdd2,stroke:#b71c1c,stroke-width:3px
```

**根本原因**:
> 当用户清理 Cookie 后，请求被 `AnonymousCache` 中间件拦截，直接返回缓存的匿名页面，请求根本不会到达 Controller，太湖自动登录逻辑无法执行。

### 问题 #3: SPA 单页应用特性

```mermaid
flowchart LR
    subgraph 首次HTML请求
        A1[服务端渲染] --> A2[preloadedData]
        A2 --> A3["currentUser: null ❌"]
    end
    
    subgraph Ember.js 初始化
        B1[读取 preloadedData] --> B2[注册 currentUser service]
        B2 --> B3["service = null 🔴"]
    end
    
    subgraph 页面内导航 XHR
        C1[点击话题/分类] --> C2[发送 AJAX 请求]
        C2 --> C3[Cookie 有效 ✅]
        C3 --> C4[后端认证成功 ✅]
        C4 --> C5["但前端 currentUser 仍是 null ❌"]
    end
    
    A3 --> B1
    B3 --> C1
    
    style A3 fill:#ffcdd2,stroke:#b71c1c,stroke-width:2px
    style B3 fill:#ffcdd2,stroke:#b71c1c,stroke-width:2px
    style C5 fill:#ffcdd2,stroke:#b71c1c,stroke-width:2px
```

**根本原因**:
> SPA 的 `currentUser` service 只在首次页面加载时从 `preloadedData` 初始化。如果首次请求返回的 `currentUser` 是 `null`，后续的 XHR 请求即使 Cookie 有效，前端也不会自动更新 `currentUser`。

## ✅ 修复方案

### 修复 #1: 使用 `prepend_before_action`

```ruby
# ❌ 修复前
before_action :auto_login_with_tai_hu_token,
              before: :redirect_to_login_if_required

# ✅ 修复后
prepend_before_action :auto_login_with_tai_hu_token,
                      if: -> { SiteSetting.tai_hu_auth_enabled }
```

### 修复 #2: 扩展 AnonymousCache

```ruby
module TaiHuAnonymousCacheExtension
  def cacheable?
    # 🔑 关键：有太湖 header 时，跳过匿名缓存
    return false if @env["HTTP_X_TAI_IDENTITY"].present?
    super
  end
end

Middleware::AnonymousCache::Helper.prepend(TaiHuAnonymousCacheExtension)
```

### 修复 #3: 为已有会话也设置 env 缓存

```ruby
def auto_login_with_tai_hu_token
  existing_user = check_existing_session_without_caching
  
  if existing_user.present?
    # 🔑 关键修复：即使已有会话，也要设置 env 缓存
    # 这样后续的 current_user 调用会返回正确的用户
    request.env[Auth::DefaultCurrentUserProvider::CURRENT_USER_KEY] = existing_user
    return
  end
  
  # ... 其他逻辑
end
```

## 📝 总结

| 问题 | 根因 | 解决方案 |
|------|------|----------|
| 首次登录不生效 | `before_action` 执行顺序导致 `current_user` 缓存为 `nil` | 使用 `prepend_before_action` 确保最先执行 |
| 清理 Cookie 后无法重登录 | `AnonymousCache` 中间件拦截请求 | 扩展 `cacheable?` 方法，有太湖 header 时跳过缓存 |
| SPA 内导航没有登录态 | 已有会话时未设置 `env` 缓存 | 为所有带太湖 header 的请求设置正确的用户缓存 |
